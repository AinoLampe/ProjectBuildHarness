# T-080 — Ticket DAG (parse, cycle detection, topological sort)

**Phase:** v0 — Walking skeleton
**Module(s):** `src/harness/dag.py`

## Goal
Turn ticket connections into a dependency graph, detect cycles, and produce a
deterministic build order (a topological sort), so Stage 3 implements tickets in
dependency order (concept §9.1, §10.2).

## Creates / changes
- `dag.py` — pure logic over parsed ticket data:
  - parse `Connections` (`blocks` / `depends on` / `relates to`) into a graph
    (`relates to` is non-blocking and ignored for ordering).
  - cycle detection raising `DagCycleError` naming the cycle.
  - topological sort yielding a **stable, deterministic** build order.

## Acceptance criteria
- A valid graph yields a topological order in which every `depends-on` precedes
  its dependent.
- A cyclic graph raises `DagCycleError` identifying the cycle.
- An empty DAG is handled (empty order, no error).
- Ordering is deterministic across runs given the same input (stable tie-break).
- The core is a pure function over parsed ticket records (a thin reader may live
  alongside it but the sort/cycle logic takes structured input).

## Out of scope
- Reading ticket files from disk as the primary concern (folder/T-040 + a thin
  parser feed it; keep the algorithm pure).
- Generating tickets (T-190 produces the overview DAG that this consumes).

## Connections

- **Relates to:** T-040.
