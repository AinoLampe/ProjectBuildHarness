# T-230 — CLI (typer entry points)

**Phase:** v0 — Walking skeleton
**Module(s):** `src/harness/cli.py`

## Goal
Provide the CLI-first interface that drives the orchestrator and maps cleanly
onto the interactive gates (concept §17).

## Creates / changes
- `cli.py` — typer commands:
  - `harness run --project <dir> [--from <stage>]` — run the full pipeline, or
    resume from a stage.
  - `harness status --project <dir>` — show journal / progress.
  - `harness gate --project <dir> --approve | --edit | --reject` — drive a gate
    decision.
  - wires the orchestrator (T-220) and config (T-030); `status` reads the journal
    (T-050); `gate` drives gates (T-150).

## Acceptance criteria
- `run` invokes the orchestrator; `--from` resumes from the named stage.
- `status` prints the current journal/progress.
- `gate` applies approve / edit / reject to the pending gate.
- Commands are type-driven (typer) with help text and meaningful exit codes.
- Tested via typer's test runner against the orchestrator with fakes.

## Out of scope
- Web UI (v2) — justified only once gate UX becomes the bottleneck (concept §17).
- Rich TUI / progress animations.

## Connections
- **Depends on:** T-220, T-030, T-050, T-150.
- **Blocks:** none (top of the stack).
- **Relates to:** T-240 (e2e can drive via the CLI or the orchestrator directly).

## Testing
**Test-after** (CLI integration) with the typer runner + fakes. Cases: `run`
happy path; `--from` resume; `status` output; each `gate` decision; bad-args exit
codes.
